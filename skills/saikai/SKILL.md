# 再開（/saikai）

前回セッションの保存状態から作業を再開する。

## 実行手順

### Step 1: 状態読み込み（軽量）

以下の 2 つだけを読む（日報・claude-mem 等は読まない）：

1. **Plans.md**: 末尾側から走査し、「✅ 再開済み」マークが付いていない**最新の**「中断メモ」または「次回セッション（引き継ぎ）」セクションを 1 つ特定する
2. **git 状態**: `git status` と直近コミット数件（`git log --oneline -5`）を確認し、メモとの食い違いを検出する
   - 未コミット変更がある → メモに書かれていない作業が進んでいる可能性
   - メモの日時より後のコミットがある → メモが古い可能性

**フォールバック**: Plans.md が存在しない、または未消化のメモが無い場合は、git log と作業ディレクトリの状況から現在地を推測し、「引き継ぎメモは見つかりませんでした（推測ベースです）」と正直に報告する。捏造しない。

### Step 2: 現在地サマリ提示

以下を簡潔に提示する（全体で 10 行以内目安）：

- **前回どこまで**: メモの WIP ＋ git 状態からの補足
- **ブロッカー**: メモにあれば
- **食い違い**: メモと git 状態がズレていれば明示

続けて AskUserQuestion で「どのアクションから再開するか」を選ばせる：

- 選択肢はメモの「次のアクション」を先頭候補にした 1〜3 個
- 最後の選択肢として「別の作業をする（メモは消化済みにする）」を含める
- 情報が足りなそうなら、質問の前に「直近の日報も読めます」と一言添える（読むのは指示があったときだけ）

### Step 3: 消化済みマークと着手

1. ユーザーがアクションを選んだら、読み込んだメモの見出し行に `（✅ 再開済み YYYY-MM-DD）` を追記する
   - 例: `## 中断メモ（2026-08-06 15:30）（✅ 再開済み 2026-08-07）`
   - メモ本文は削除・変更しない（履歴として残す）
2. そのまま選ばれた作業に着手する

---

## 注意事項

- 読み込みは Plans.md ＋ git 状態のみ。速さ優先。日報・claude-mem・manual-todo state はユーザーの指示があったときだけ読む
- 消化済みマークは**ユーザーがアクションを選んだ後**に付ける（提示だけして中断した場合は未消化のまま残す）
- 「次回セッション（引き継ぎ）」セクションに未完了の残タスク（`- [ ]`）が複数あり、一部だけ着手する場合もセクション自体には消化済みマークを付ける（残タスクのチェックボックスが未完了状態の正本）
- 中断側の保存は /nakajime（軽量）・/shime（日報つき）を使う。本スキルは読み込み側のみ
