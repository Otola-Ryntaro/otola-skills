# チェック手順（WebSearch）

Phase ⑤ で 10候補それぞれに対して実行する確認手順をまとめる。

> **重要原則**: WebSearch の結果はあくまで **目安・初期スクリーニング**。本気で衝突回避するなら、商標は J-PlatPat（日本）/ USPTO（米国）等での正式な商標検索、ドメインは各レジストラの whois 確認、法的判断は弁理士相談が必要。スキルとしては「一次フィルタ」を担うが、**「絶対に安全」「商標上問題ない」とは絶対に言わない**。

---

## 4 つの確認観点

### 1. 既存サービス・商標衝突

**狙い**: 同名/類似名の有名サービス・登録商標がないかを確認。

**クエリ例**:

```
"<候補名>" サービス
"<候補名>" アプリ
"<候補名>" 会社
"<候補名>" 医療
"<候補名>" service
"<候補名>" app
"<候補名>" software
"<候補名>" startup
"<候補名>" trademark
```

**確認すべきプラットフォーム**（必要に応じて追加検索）:

- Google 検索（一般）
- App Store / Google Play（モバイルアプリ）
- X / Instagram / YouTube（SNS ハンドル衝突）
- 日本の商標検索（J-PlatPat）
- 海外商標データベース（TMview, USPTO）

**判定**:

- 同じドメイン・同じターゲット層に有名サービスが存在 → **落とす**
- 同名サービスが完全一致で存在（ジャンル問わず）→ 原則 **落とす**（混同リスクが高い）
- 別ジャンル・別地域に小規模に存在 → 注記して残す（最終判断はユーザー）
- 全く見当たらない → クリア

**判定時の注意**:

- 一般名詞や短い造語は検索ノイズが多くなる → **完全な未使用性だけでなく、サービス領域での混同可能性を重視**
- 「同名のレストラン」「同名のローカル店」は混同リスクが低ければ残してよい

### 2. 各国スラング・不適切語

**狙い**: 主要言語で下ネタ・差別語・宗教的タブー・侮蔑語に該当しないか確認。

**チェックする言語**（候補のターゲット市場に応じて優先順を調整）:

- 英語（必須）
- 日本語（不自然な意味がないか）
- 中国語（標準語・広東語）
- 韓国語
- スペイン語（中南米・米国南部市場）
- ドイツ語
- フランス語
- ポルトガル語（ブラジル市場狙うなら）

**クエリ例**:

```
"<候補名>" slang
"<候補名>" meaning
"<候補名>" urban dictionary
"<候補名>" offensive
"<候補名>" bad meaning
"<候補名>" Japanese meaning
"<候補名>" Korean meaning
"<候補名>" Chinese meaning
"<候補名>" Spanish meaning
"<候補名>" German meaning
"<候補名>" 意味
"<候補名>" 韓国語 意味
```

**判定**:

- 明確な下ネタ・差別語・侮蔑語・宗教的タブー → **必ず落とす**（理由を明示）
- 微妙にネガティブな意味あり → 注記して残す
- 信頼性が必要な領域（医療・教育・金融）で不利な響き → 残すが警告

**情報源の扱い**:

- Urban Dictionary など低信頼ソースは過度に重視しない
- ただし、明確に性的・差別的・侮辱的な意味がある場合は候補から外す
- 複数ソースで同じ指摘がある場合は重く扱う

### 3. ドメイン空き状況（目安）

**狙い**: `.com` / `.jp` / `.app` などが既に商用利用されていないかを WebSearch ベースで概算する。

**クエリ例**:

```
<候補名>.com
<候補名>.jp
<候補名>.app
<候補名>.io
<候補名>.net
site:<候補名>.com
```

**判定**:

- 検索結果上位にその名前のサイトが大量に出る → ドメイン取得は困難な可能性大、要注記
- 検索結果が出ない/関連無し → 空いている可能性あり（要レジストラ確認）

> **必ず伝える**: 「WebSearch では空きの確証は取れません。実際の取得可否は Cloudflare Registrar / お名前.com / Google Domains 等で whois 確認してください」

### 4. 多言語発音

**狙い**: 主要言語で読み上げ困難・誤読されない綴りかを評価。

**確認方法**:

- 綴りを見て、英語/日本語/スペイン語/ドイツ語ネイティブがどう読むか推測
- 必要に応じて `"<候補名>" pronunciation` で WebSearch
- 主要言語で大きく異なる読みになる場合は注記

**判定**:

- 全主要言語で概ね同じ音で読まれる → ◎
- 一部言語で誤読されるが致命的でない → ○
- 多くの言語で読みが分かれる、または日本人ですら読めない → △ または落とす

## 効率的な束ね方

10候補 × 4観点 = 40 クエリは多すぎる。**WebSearch を並列発行 + クエリを束ねる**。

### 推奨パターン

各候補につき **2 クエリ** に集約する例:

**クエリ A（衝突・商標）**:
```
"<候補名>" service app trademark startup
```

**クエリ B（スラング・意味）**:
```
"<候補名>" meaning slang
```

→ ドメインと多言語発音は綴りベースで推論し、必要な候補だけ追加調査。

### 並列発行

10候補のクエリ A を全部並列で投げる → クエリ B を全部並列で投げる、の 2 ラウンドで済む。WebSearch 結果が返ってきたら一覧表にまとめる。
