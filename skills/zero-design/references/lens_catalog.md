# 観点カタログ（lens catalog）

zero-design Phase 2 で提案する調査観点の候補一覧。
**ここから全部使うのではなく、ユーザーの動機 × Phase 1 の兆候 × プロジェクト種別に合うものを 3〜6 個選ぶ。**
該当しない観点は提案しない（例: CLI にフロントエンド、UI なしライブラリに a11y）。

| 観点 | 調査対象 | 向いているケース |
|------|---------|-----------------|
| アーキテクチャ | ディレクトリ構造、レイヤリング、依存方向、循環参照、ルーティング | 「変更しにくい」「どこに何があるか分からない」 |
| ドメインロジック | ビジネスルールの置き場所、重複実装、暗黙の仕様、境界の曖昧さ | 「同じバグが再発する」「仕様が散らばっている」 |
| データモデル | スキーマ設計、テーブル関係、インデックス、正規化、マルチテナント | DB のあるアプリ全般、「クエリが遅い」「整合性事故」 |
| フロントエンド | コンポーネント構成、状態管理、レンダリング戦略、UIライブラリ | Web アプリで UI の保守性・速度に不満 |
| テスト戦略 | カバレッジの偏り、テストの種類バランス、flaky、実行時間、モック濫用 | 「テストが信用できない」「リグレッションが漏れる」 |
| エラー処理・回復性 | 例外の握り潰し、エラーメッセージ、リトライ、graceful degradation | 「本番で謎の落ち方をする」「調査に時間がかかる」 |
| セキュリティ | 認証認可、入力検証、シークレット管理、RLS/テナント分離 | 外部公開サービス、決済・個人情報を扱う |
| パフォーマンス | N+1、バンドルサイズ、キャッシュ、メモリ、ホットパス | 「遅い」という具体的な体感・計測がある |
| 依存管理 | 依存の鮮度、重複、CVE、メンテ状況、置き換え候補 | 長期運用リポジトリ、アップグレード恐怖症 |
| インフラ・DX | CI/CD、環境変数管理、デプロイ、ローカル開発体験 | 「デプロイが怖い」「セットアップに半日かかる」 |
| 運用・可観測性 | ログ、モニタリング、アラート、障害時の追跡可能性 | 本番運用中で「何が起きてるか分からない」 |
| アクセシビリティ | WCAG、キーボード操作、スクリーンリーダー | 公開 Web UI があり、a11y が要件のとき |
| ドキュメント・引き継ぎ性 | README、CLAUDE.md、暗黙知の文書化度合い | 「自分以外（未来の自分含む）が触れない」 |

## 選択の指針

- ユーザーの動機に直接対応する観点を最低1つ入れる
- Phase 1 の兆候（巨大ファイル・error-patterns 既知パターン・テスト欠如など）が指す観点を優先する
- 迷ったら観点を減らす。3個の深い調査は6個の浅い調査に勝る
