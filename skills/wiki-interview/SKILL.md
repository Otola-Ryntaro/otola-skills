# wiki-interview — 対話で「育てる問い」を引き出す（裏取りはしない）

ユーザーの頭の中にある思考・コメント・違和感を **インタビューで引き出し**、wiki-prospect が育てられる
「育てる問い（seed）」に磨く。**外（Web）から集めるのは wiki-prospect の仕事**。ここは引き出すだけ。

## 🔴 鉄則
- **先に Web 検索・WebFetch しない**（このスキルにそのツールは持たせていない）。引き出す段階に徹する。
- **質問は1問ずつ、通常メッセージで**投げる。質問攻めにしない。ユーザーの自由記述が主役。
- Claude は **要約・整理・問い化** に徹する。ユーザーが言っていないことを足さない・捏造しない。
- **編集判断はユーザーが握る**。seed にするか・優先度・着地先は最後に必ず承認を取る。

## 最初に読む（正本・必要時のみ）
- `~/Obsidian/LLM_Wiki/config.md` … ドメイン定義（`medical-science` / `society-thought` / `investment` / `ai-tech`）。
- `~/Obsidian/LLM_Wiki/interests/questions.md` … seed の登録先と記法。
- `~/Obsidian/LLM_Wiki/CLAUDE.md` … schema（手動運用・人間が編集判断・事実↔意見リンク）。

## Phase 0: 起点の判定
ユーザーの発話から「**新規の芽**（まだ wiki に無い思いつき・コメント）」か
「**既存ページの深掘り**（concept/opinion を対話で深める）」かを見極める。曖昧なら `AskUserQuestion` で1問だけ確認。

## Phase 1: 起点の取り込み
- **新規の芽**: ユーザーの最初のコメント（1〜3行）をそのまま起点にする。調べに行かない。
- **既存深掘り**: 対象ページを `Glob`/`Grep`（`wiki/concepts/`・`wiki/opinions/`）で特定し `Read`。
  **勝手に書き換えない**（読むだけ。更新は後段の wiki-prospect/absorb の仕事）。

## Phase 2: インタビュー（自由記述中心）
下の「問いの型」から流れで取捨選択し、**1問ずつ**投げる。全部を機械的に聞かない。
ユーザーが「もう十分」と言うまで、または論点（=問い）が立ち上がるまで続ける。回数は固定しない。

**問いの型:**
1. **出どころ** — これは経験から？それとも一般論・読んだことから？
2. **核** — 何が引っかかる／面白い／違和感がある？
3. **狙い** — 誰に伝えたい？何を説得・言語化したい？
4. **裏付けの種** — 思い当たる具体例・数字・エピソードは？
5. **対立軸** — 反対の見方・ありそうな反論は？
6. **裏取りの方向** — wiki に落とすなら何を調べるべき？（→ これが seed の「論証の方向」になる）

## Phase 3: 芽の構造化
対話結果を次の形に整形して提示し、**ユーザーの承認を待つ**（勝手に確定しない）:
- `domain`（config の4つから）/ `優先度`（P1〜P3）/ `磨いた問い` / `論証の方向（対立軸メモ）`

## Phase 4: questions.md へ追記（外科的）
承認された seed を `interests/questions.md` の
**`## 対話seed由来（育てる候補｜wiki-interview の対話から）`** セクションへ追記する（無ければ末尾付近に新設）。
**既存行は触らない。** 記法は既存に厳密にそろえ、1行で書く:

```
- [ ] (<domain> / <P1-P3> / open) <磨いた問い> — <論証の方向・対立軸メモ>
```

## Phase 5: hand-off
「いま **wiki-prospect** で Web 裏取り・育成まで進めますか？」と確認する。
- **はい** → `Skill` で wiki-prospect をトピック指定起動（「〈問い〉を深掘りしてwikiに」）。
- **いいえ** → seed 登録で停止（後日ユーザーが手動で wiki-prospect を回す）。

## 注意
- 手動トリガ・引き出し→承認を厳守。自動で調べない・自動で書かない。
- 既存ページのコピーや書き換えはしない（参照のみ）。育成・統合は wiki-prospect / wiki-absorb に委ねる。
