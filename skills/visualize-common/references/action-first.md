## セクション順序（固定）

可視化 HTML は必ずこの順で構成する。開いた瞬間（ファーストビュー）に 1〜2 が見えること。

1. **Hero「今すぐやること」** — `.hero` カード。ユーザーの最重要アクション 1〜3 個。
   コマンドはコピペ可能な `<code>`、URL は最深部の直リンク。
   「次に何もすることが無い」場合のみ Hero を「✅ このセッションで完結。やることはありません」に差し替える。
2. **なぜ今これか** — Hero 直下に 1〜2 段落の地の文。何が起きてこのアクションが必要になったのか、
   やらないと何が困るのかを文章で説明する。
3. **スクショギャラリー** — 該当する画像があれば `.shots` セクション（→ `screenshot-embed.md`）。無ければ省略。
4. **詳細・経緯** — 従来の本文（やったこと・変更ファイル・完了/未完了・決定事項など）。
5. **参考情報・付録** — リンク・用語・フッタ。

Hero の HTML 雛形:

```html
<div class="hero">
  <div class="ttl">⚡ 今すぐやること</div>
  <div class="action">1. {{ACTION_1}}</div>
  <p class="why">{{ACTION_1_WHY — なぜこれをやるのか 1 文}}</p>
  <div class="action">2. {{ACTION_2}}</div>
  <p class="why">{{ACTION_2_WHY}}</p>
</div>
```

## 文章量ガイドライン

- **各 h2 セクションの見出し直下に、必ず 2〜4 文の地の文**を置く。表・カード・箇条書きに入る前に、
  「このセクションは何で、なぜ読む価値があるか」を文章で書く。
- **箇条書きのみのセクション禁止**。リスト項目にも可能な限り 1 文の補足（なぜ・どうなる）を添える。
- アクション項目は「具体動詞 + 対象 + 結果状態」で書く（manual-todo 規約と同一）。
  「設定する」は失格、「◯◯画面で△△をコピーして□□に貼ると××が有効になる」が合格。
- 専門用語・内部処理用語（claim_id / ledger / Phase 番号など）は読者向け HTML に出さない。
  ノンプログラマ（音良林太郎）が読んで理解できることが合格基準。

## セクション省略ルール

- データが無いセクション（スクショ無し・未完了ゼロ等）は空のまま残さず、セクションごと省略する。
- ただし Hero（1）と「なぜ今これか」（2）は省略不可。
