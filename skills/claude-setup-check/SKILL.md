# claude-setup-check: Claude Code 構成ベストプラクティス診断

プロジェクトの `.claude` フォルダ構成を診断し、ベストプラクティスへの準拠度をスコア付きで報告する。
コード変更は一切行わない。診断とレポート出力のみ。

## チェック項目一覧

全7カテゴリ、各カテゴリに複数チェック項目がある。

### Category 1: CLAUDE.md（配点: 25点）

| # | チェック | 配点 | 判定基準 |
|---|---------|------|----------|
| 1.1 | CLAUDE.md 存在 | 5 | プロジェクトルートに CLAUDE.md が存在するか |
| 1.2 | 行数が適切 | 5 | 50〜200行が理想。200行超はペナルティ、20行未満も減点 |
| 1.3 | コマンド記載 | 5 | ビルド・テスト・lint 等の実行コマンドが記載されているか |
| 1.4 | アーキテクチャ記載 | 5 | 技術スタック・ディレクトリ構造の説明があるか |
| 1.5 | 注意事項記載 | 5 | gotcha / 注意点 / ルールが記載されているか |

## 実行プロトコル

### Phase 1: 情報収集（並列実行）

以下を**並列で**実行し、情報を収集する:

```
1. プロジェクトルートの CLAUDE.md を Read（存在確認 + 内容分析）
2. .claude/ ディレクトリ構造を Bash(ls -la) で取得
3. ~/.claude/ ディレクトリ構造を Bash(ls -la) で取得
4. .claude/settings.json を Read（存在確認 + 内容分析）
5. ~/.claude/settings.json を Read
```

### Phase 2: 各カテゴリ判定

収集した情報をもとに、各チェック項目を判定する。

**判定ルール:**
- 存在チェック: ファイル/ディレクトリの有無
- 内容チェック: キーワード検索（Grep）で該当セクションの有無を確認
- 行数チェック: `wc -l` で計測
- frontmatter チェック: `---` で囲まれた YAML ブロックの有無
- path-scoped チェック: `paths:` キーワードの有無（ソースコードがないドキュメント専用プロジェクトはスキップ可）

**プロジェクト種別の考慮:**
- ソースコードがないプロジェクト（ドキュメント専用リポ等）では以下を減点対象外にする:
  - path-scoped ルール（2.3）
  - ビルド/テストコマンド記載の一部（1.3）
- その場合、配点を再配分して100点満点を維持する

### Phase 3: スコア算出

```
合計スコア = 各項目のスコア合計（100点満点）

ランク:
  90-100: S（模範的）
  80-89:  A（優秀）
  70-79:  B（良好）
  60-69:  C（改善余地あり）
  0-59:   D（要改善）
```

以下の形式でレポートを出力する（ターミナルに直接表示）:

## 注意事項

- このスキルはコードを一切変更しない（読み取りと診断のみ）
- グローバル（~/.claude/）とプロジェクトレベル（.claude/）の両方をチェックする
- プロジェクト種別（ソースコード有無）を自動判定し、配点を適切に調整する
- 改善アクションは具体的かつ実行可能な内容にする
